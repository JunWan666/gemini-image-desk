# Design Rules

## Visual Direction

整体风格应是安静、专业、轻量的创作工作台。避免做成营销页、模板站或过度装饰的 AI 工具首页。

## Layout

- 桌面端使用三栏布局。
- 中间创作区优先级最高，占据最大宽度。
- 左侧配置区适合窄一些，右侧参数/历史区适合可折叠。
- 窄屏时改为顶部配置 + 主创作区 + 底部/抽屉式历史。

## Components

- 顶层页面分区使用面板，不使用大面积嵌套卡片。
- 图片结果可以使用卡片，因为它是重复项目。
- Prompt 区要像编辑器，不像普通表单。
- 历史记录应支持快速扫描：缩略图、短 prompt、模型、时间。
- 主要操作按钮只能有一个：生成/重新生成。

## Color

- 基础色使用中性背景、边框和文本层级。
- 允许使用少量蓝、绿、黄、红表示操作和状态。
- 避免全页面蓝紫渐变、暗蓝 slate 风格或单一色相 UI。
- 错误、警告、成功状态必须可读，不能只靠颜色表达。

## Typography

- 工具界面使用紧凑但可读的字号。
- 不使用 hero 级标题。
- 按钮、标签、模型名称要能截断或换行。
- 不使用负 letter spacing。

## Interaction

- 上传图片后立即显示缩略图。
- 生成时保持布局稳定，不让结果区高度剧烈跳动。
- 长任务要显示明确进度状态，至少包括 pending/running/error/success。
- 图标按钮必须有 tooltip 或 aria-label。
- 下载、继续编辑、删除这些动作应靠近图片结果。

## Empty States

- 空结果区应简洁，提示用户输入 prompt 或上传参考图。
- 不要用大段说明文字讲功能。
- 错误信息要告诉用户下一步可以做什么，例如检查 Key、模型或网络。
